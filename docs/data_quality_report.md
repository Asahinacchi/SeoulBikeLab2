# Отчёт о качестве данных — Seoul Bike Sharing Demand

## 1. Контекст и входные данные

Цель обработки — подготовить почасовые наблюдения Seoul Bike Sharing Demand для последующего анализа спроса по времени суток, сезонам, типам дней и погодным условиям.

Основной аналитический вопрос: в какие часы, сезоны и типы дней наблюдается наиболее высокий и низкий спрос на аренду велосипедов?

Исходный объект читается непосредственно из SeaweedFS с помощью DuckDB:

`s3://raw/seoul_bike/ingested_on=2026-10-13/SeoulBikeData.csv`

Одна строка соответствует одному часу определённой даты. Бизнес-ключ — комбинация `Date + Hour`. Исходный объект `raw` не изменялся.

## 2. Профиль данных

Исходный CSV содержит 8760 строк и 14 полей. Период наблюдений — с 01.12.2017 по 30.11.2018. При чтении из S3 DuckDB дополнительно распознаёт партиционное поле `ingested_on`.

| Характеристика | Результат |
|---|---:|
| Количество строк | 8760 |
| Количество полей исходного CSV | 14 |
| Уникальные даты | 365 |
| Минимальная дата | 2017-12-01 |
| Максимальная дата | 2018-11-30 |
| Повторы ключа `Date + Hour` | 0 |
| Полные дубликаты | 0 |

Для пяти значимых полей проверена полнота:

| Поле | Тип DuckDB | Пропуски |
|---|---|---:|
| `Date` | DATE | 0 |
| `Hour` | BIGINT | 0 |
| `Rented Bike Count` | BIGINT | 0 |
| `Humidity(%)` | BIGINT | 0 |
| `Functioning Day` | BOOLEAN | 0 |

Каждая комбинация даты и часа уникальна. Для каждого из 24 часов суток имеется по 365 наблюдений.

Распределение среднего количества аренд по часам показывает заметные различия во временном спросе. Наибольшее среднее значение наблюдается в 18:00 — 1502,93 аренды, наименьшее — в 04:00, 132,59 аренды. Это подтверждает необходимость учитывать час суток при последующем анализе.

Отрицательные значения температуры воздуха и точки росы допустимы по физическому смыслу и не считаются ошибками только из-за отрицательного знака. Период наблюдений ограничен одним годом, а идентификаторы отдельных станций отсутствуют.

## 3. Правила качества и результаты

Для всех правил установлен порог, равный нулю нарушений. Доля нарушений рассчитывается относительно числа проверенных строк.

| ID правила | Проверено строк | Нарушений | Доля | Порог | Превышен | Действие |
|---|---:|---:|---:|---:|---|---|
| `unique_date_hour` | 8760 | 0 | 0% | 0 | Нет | `quarantine` |
| `required_rented_bike_count` | 8760 | 0 | 0% | 0 | Нет | `quarantine` |
| `hour_in_valid_range` | 8760 | 0 | 0% | 0 | Нет | `quarantine` |
| `non_negative_rented_bike_count` | 8760 | 0 | 0% | 0 | Нет | `quarantine` |
| `humidity_in_valid_range` | 8760 | 0 | 0% | 0 | Нет | `flag` |
| `closed_system_zero_rentals` | 8760 | 0 | 0% | 0 | Нет | `quarantine` |

Проверки охватывают уникальность почасовых наблюдений, полноту целевой метрики, допустимость часа и количества аренд, диапазон влажности и согласованность работы системы с числом аренд. Критические нарушения направляются в карантин. Нарушения допустимого диапазона влажности обрабатываются предупреждающим признаком `quality_flag_humidity_out_of_range`.

По фактическим результатам нарушений не обнаружено. Поэтому все исходные записи пригодны для сохранения в `staging`, а карантин остаётся пустым.

## 4. Подготовленные данные

Результаты сохранены в SeaweedFS в формате Parquet:

- `s3://staging/seoul_bike/source_ingested_on=2026-10-13/staging.parquet`
- `s3://staging/seoul_bike/source_ingested_on=2026-10-13/quarantine.parquet`

В `staging.parquet` аналитические поля приведены к именам в формате `snake_case`. Добавлен признак `quality_flag_humidity_out_of_range`. Исходные поля карантина сохранены вместе с `quality_rule_ids` и `quarantine_reason`.

При повторном чтении обоих файлов непосредственно из S3 получены следующие количества:

| Набор | Число строк |
|---|---:|
| `raw` | 8760 |
| `staging` | 8760 |
| `quarantine` | 0 |

Баланс выполняется: `8760 = 8760 + 0`. Проверка прочитанного `staging.parquet` подтвердила отсутствие повторяющихся ключей, пропусков обязательных полей, недопустимых часов, отрицательных аренд и несогласованных записей для неработающей системы. Нарушений диапазона влажности также не обнаружено.

Пустой `quarantine.parquet` создан со схемой, включающей исходные поля и поля для идентификаторов правил и причин исключения. Исходный объект `raw` не изменялся.

## 5. Воспроизводимость и ограничения

Вся процедура реализована в `notebooks/profile_quality.ipynb`. Ноутбук повторно выполнен сверху вниз после перезапуска ядра без ошибок. Повторная обработка использует тот же входной S3-путь и тот же выходной префикс; повторное чтение результатов подтверждает количество 8760 строк в `staging` и 0 строк в карантине.

Результаты воспроизводимы для использованного исходного объекта и заданных правил. Ограничения анализа — один год наблюдений и отсутствие пространственной детализации по станциям. Отсутствие нарушений по выбранным правилам не гарантирует отсутствие всех возможных проблем качества, поэтому выводы относятся только к проверенным свойствам данных.
