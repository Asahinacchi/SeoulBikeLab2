
# Лабораторная работа № 4
## Проектирование и сборка аналитической витрины

**Проект:** Seoul Bike Sharing Demand
**Группа:** ИВТ-241

## 1. Модель

### Аналитический вопрос

В какие часы, сезоны и типы дней наблюдается наиболее высокий и низкий спрос на аренду велосипедов?

### Источник данных

В качестве источника использован подготовленный файл `staging.parquet` из лабораторной работы № 3, расположенный в S3-хранилище SeaweedFS:

`s3://staging/seoul_bike/source_ingested_on=2026-10-13/staging.parquet`

### Гранулярность и ключ

Основная таблица витрины называется `hourly_demand`.

**Одна строка таблицы `hourly_demand` представляет одно почасовое наблюдение за арендой велосипедов в определённую дату.**

Для идентификации наблюдения используется составной ключ `observation_date + hour`. Проверки подтвердили отсутствие пропусков и повторов по этому ключу.

Витрина реализована в виде одной широкой таблицы. Отдельные таблицы измерений не создавались, поскольку все необходимые атрибуты и показатели находятся в исходном `staging`.

### Меры и правила агрегации

Основная мера — `rented_bike_count`, количество аренд велосипедов за соответствующий час. Значения этой меры можно суммировать по непересекающимся часам и датам.

Для сравнения спроса по сезонам, типам дней и часам рассчитывается среднее количество аренд. При этом среднее рассчитывается только по наблюдениям, для которых `functioning_day = TRUE`, чтобы часы неработающей системы не искажали сравнение спроса.

Погодные показатели предназначены для сравнения условий наблюдения и спроса; их суммы не следует трактовать как самостоятельные показатели спроса.

### Результат сборки

Витрина сохранена в формате Parquet:

`s3://mart/seoul_bike/source_ingested_on=2026-10-13/hourly_demand.parquet`

Входной и выходной наборы содержат по 8760 строк. Исходная почасовая гранулярность сохранена, скрытая фильтрация строк не применялась.

## 3. Проверки и ограничения

### Проверки

Проверки сохранённого Parquet выполнены в ноутбуке `notebooks/build_mart.ipynb`.

Результаты:
- Входной `staging` и сохранённый `mart` содержат по 8760 строк.
- Данные охватывают 365 дат с 1 декабря 2017 года по 30 ноября 2018 года.
- Повторы составного ключа `observation_date + hour` не обнаружены.
- Пропуски в ключевых полях не обнаружены.
- Недопустимые часы, отрицательные значения количества аренд и нарушения диапазона ISO-дней недели не обнаружены.
- Противоречия между признаком работы системы и количеством аренд не обнаружены.
- Недопустимые значения `day_type` не обнаружены.
- Флаги влажности сохранены; несоответствий между флагами и фактическими значениями влажности не обнаружено.
- Число строк после сохранения в S3 не изменилось.

### Проверка пригодности для аналитического вопроса

Выполнена группировка по сезонам, типам дней и часам. Для каждого среза рассчитано среднее количество аренд среди наблюдений, когда система работала.

Среди десяти срезов с наибольшим средним спросом первое место занял летний будний день в 18:00 — 2327,36 аренды. Среди десяти срезов с наименьшим средним спросом минимальное значение составило 37,19 аренды зимой в выходной день в 05:00.

### Ограничения

Данные представляют почасовые наблюдения, а не отдельные события аренды. Поэтому количество строк нельзя интерпретировать как число аренд.

Набор охватывает один год наблюдений. Полученные результаты описывают только этот период и сами по себе не доказывают долгосрочные закономерности.

Неработающие часы сохранены в витрине. Для сравнения среднего спроса они исключаются из расчёта, но остаются доступными для других проверок и анализов.

Количество строк с установленным флагом влажности в текущем наборе равно нулю.
